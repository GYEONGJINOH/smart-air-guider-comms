# Smart Air Guider — Arduino TinyML 인체 추종 설계서

> 기존 [smart-air-guider.vercel.app](https://smart-air-guider.vercel.app/) 대시보드의 데이터 스키마
> (`temperature / humidity / power / x / y / z / yaw / pitch / mode`)를 **그대로 유지**하면서,
> 그 값을 만들어내는 방식을 "PIR 3존 + 클라우드 의존"에서 "온디바이스 TinyML + 오프라인 우선"으로
> 교체하는 설계다.

---

## 0. 요구사항 → 설계 결정 매핑

| 요구사항 | 현재 구현의 한계 | 도출한 해법 |
|---|---|---|
| 에어컨이 **사람을 인식** | PIR는 "움직임 유무"만 감지. 반려동물·TV·햇빛 벽면과 사람을 구분 못 함 | 32×24 열화상 + 24GHz 레이더를 입력으로 하는 **CNN(TinyCenterNet) 온디바이스 추론** |
| 사람을 **따라감** | `zones[]`의 하드코딩 좌표 3개(-100/0/+100cm)로 점프 | 히트맵 peak → 각도 → **칼만 필터 추적** → 슬루 제한 서보 2축 조준 |
| **멀리서도** 작동 | PIR ~5m, 원격 제어는 인터넷 경유 | ① 감지: 열화상+레이더 융합 6~8m, 부족 시 **멀티노드 ESP-NOW 메시** ② 제어: **ESP-NOW / LoRa / BLE** (라우터·인터넷 불필요) |
| **인터넷이 안 돼도** AI가 알아서 | `while(WiFi.status()!=WL_CONNECTED)` 무한 블로킹 → 제어 루프 정지 | **제어 루프와 네트워크의 완전 분리**. 추론·제어는 100% MCU 내부, 네트워크는 best-effort 백그라운드 + 로컬 링버퍼 백필 |

설계 원칙 한 줄: **네트워크는 "관측용 부가기능"이지 제어 경로가 아니다.**

## 2. 하드웨어 선정

### 2.1 MCU

| 후보 | RAM / Flash | TinyML 적합성 | 판정 |
|---|---|---|---|
| **ESP32-S3** (DevKitC-1 / XIAO ESP32S3) | 512KB SRAM(+PSRAM) / 8MB | ESP-NN 벡터 가속 커널, TFLM 공식 포트(`esp-tflite-micro`) | **채택** |
| Arduino Nano 33 BLE Sense Rev2 | 256KB / 1MB | TFLM 레퍼런스 보드지만 Cortex-M4F 64MHz로 느림, ESP-NOW 없음 | 대안 |
| Arduino Nicla Vision | 1MB / 2MB | 카메라 내장·성능 우수하나 고가, 무선이 WiFi/BLE뿐 | 비전 확장 시 |
| ESP32(기존) | 520KB / 4MB | 동작은 하나 ESP-NN 미지원 → 추론 2~3배 느림 | 비권장 |

**ESP32-S3 채택 이유**: (a) 기존 저장소가 이미 ESP32 Arduino 코드베이스 → 코드 자산 재사용, (b) **ESP-NOW**로 라우터·인터넷 없이 원거리 제어가 가능한 유일한 후보, (c) ESP-NN int8 가속으로 8Hz 추론 여유 확보. Arduino IDE/CLI로 그대로 빌드하므로 "Arduino TinyML"의 범주 안에 있다.

### 2.2 센서 — 왜 이 조합인가

| 센서 | 역할 | 강점 | 단점 |
|---|---|---|---|
| **MLX90640** (32×24 열화상, 55°×35° 또는 110°×75°) | 주 인식 | 완전 암전 동작, 카메라 아님 → 프라이버시, **정지한 사람도 감지** | 실내 온도가 체온에 근접하면 대비 저하, 유리 너머 불가 |
| **HLK-LD2450** (24GHz mmWave, 최대 3인 x·y 좌표 출력) | 거리·움직임 보강 | 정확한 **레인지(z)**, 어둠·연기 무관, 열원 오검출 없음 | **정지 상태 감지 취약**, 커튼/선풍기 오검출 |
| DHT22 / SHT31 | 온습도 | 스키마의 `temperature/humidity` | — |
| PZEM-004T v3 (또는 기존 INA219) | 소비전력 | AC 220V 실측. INA219는 DC 전용 | 결선 시 활선 주의 |
| HC-SR501 PIR (기존 유지) | 웨이크업 트리거 | 극저전력, 무인 시 추론 정지 | 방향 정보 없음 |

**핵심**: 두 센서의 실패 모드가 **정확히 상보적**이다.
- 열화상 실패 케이스 = 실내 온도 30℃ 이상 / 두꺼운 옷 → 이때 사람은 대개 움직임 → **레이더가 잡음**
- 레이더 실패 케이스 = 소파에서 정지 → 이때 사람은 확실한 열원 → **열화상이 잡음**

이 상보성이 "인터넷 없이도 AI가 알아서" 요구를 만족시키는 신뢰성의 근거다. 단일 센서 + 임계값 방식으로는 절대 도달할 수 없고, 두 스트림을 융합해 판단하는 데 학습 모델이 필요하다.

### 2.3 액추에이터

- 서보 2축: yaw MG996R (±60°, 루버 좌우), pitch MG90S/MG996R (±30°, 베인 상하)
- **별도 전원 5V/3A 필수** — 서보 인러시가 MCU 레일을 끌어내리면 I2C 열화상이 깨진다. 공통 GND, 470µF 벌크 커패시터
- IR LED + 트랜지스터 → 에어컨 본체 전원/설정온도/풍량 제어 (`IRremoteESP8266`)
- 순정 에어컨을 개조하지 않는 전제: 토출구 앞 **외장 2축 베인 어태치먼트**(3D 프린트) 방식 권장

### 2.4 물리 배치 및 좌표계

```
        y↑ (위)
         │
         │   ● 사람 (x, y, z)
         │  ╱
         │ ╱
    ─────●───────▶ z (전방)
        ╱ 원점 = 에어컨 토출구 중심
       ╱
      x (오른쪽)
```

- 열화상/레이더는 토출구 상단, 지면 기준 높이 `MOUNT_HEIGHT_CM`에 **정면 부착**
- 센서 원점과 토출구 원점의 오프셋 벡터 `SENSOR_OFFSET_{X,Y,Z}`를 config에 명시 → 조준 계산 시 보정
- 대시보드의 X/Y/Z cm가 이 좌표계 값

## 3. TinyML 모델 설계

### 3.1 무엇을 학습시키는가

임계값 방식(`if (pixel_temp > 30) 사람`)이 실패하는 지점을 학습이 메운다:

| 오검출 원인 | 임계값 방식 | CNN이 배우는 단서 |
|---|---|---|
| 햇빛 든 벽/바닥 | 오검출 | 넓고 균일한 영역 + 시간 변화 없음 + 레이더 무반응 |
| 노트북/TV/전기포트 | 오검출 | 직사각형 형상, 고정 위치, 온도 프로파일 평탄 |
| 반려동물 | 오검출 | 작은 blob + 낮은 높이 + 빠른 불규칙 이동 |
| 여름철 실내 28℃, 체온 33℃ | 미검출(대비 부족) | 배경 차분 정규화 + 사람 형상의 **공간 그래디언트 패턴** |
| 두꺼운 옷/이불 | 미검출 | 노출 피부(얼굴·손)의 국소 핫스팟 패턴 |

### 3.2 입력 전처리 (실내 온도 불변성 확보)

이 단계가 모델 성능의 절반을 결정한다. 냉방 중에는 실내 온도가 계속 변하므로 **절대 온도를 그대로 넣으면 안 된다.**

```
raw[24][32]  (℃, float)
  │
  ├─ ① 배경 모델 B: 픽셀별 30초 롤링 20-percentile (정지 열원 흡수)
  │
  ├─ ② 대비 정규화:  N = (raw - median(raw)) / max(3·σ(raw), 1.5)
  │                  clip [-1, +3] → int8 [-128, 127]
  │        ※ median 기준이라 실내 온도가 22℃든 30℃든 동일 분포
  │
  ├─ ③ 시간 차분 채널:  D = raw[t] - raw[t-1s]   (움직임/신규 열원)
  │                     동일 스케일로 int8 양자화
  │
  └─▶ 입력 텐서 [24, 32, 2] int8   (= 1536 bytes)
```

레이더는 CNN에 넣지 않고 **후단 융합**한다(§4.2). 이유: 레이더 출력이 이미 고수준 좌표라 CNN에 넣으면 모델이 레이더에 과의존해 정지 인물에서 무너진다. 두 경로를 독립적으로 유지해야 상보성이 살아난다.

### 3.3 네트워크 구조 — TinyCenterNet

```
Input 24×32×2 (int8)
 ├ Conv3×3, 16, s2, BN, ReLU6            → 12×16×16
 ├ DWSepConv3×3, 32, s1, BN, ReLU6       → 12×16×32
 ├ DWSepConv3×3, 64, s2, BN, ReLU6       →  6× 8×64
 ├ DWSepConv3×3, 64, s1, BN, ReLU6       →  6× 8×64
 └ Head (1×1 Conv, 병렬 3개)
     ├ heatmap  6×8×1  sigmoid   ← 사람 중심 확률
     ├ offset   6×8×2  linear    ← 셀 내 서브픽셀 보정 (각도 정밀도)
     └ logdepth 6×8×1  linear    ← 레이더 없을 때의 거리 폴백
```

| 항목 | 값(설계 목표) |
|---|---|
| 파라미터 | 약 2.4만 개 |
| int8 모델 크기 | 약 30 KB (Flash) |
| Tensor arena | 약 48 KB (SRAM) |
| 추론 시간 | ESP32-S3 240MHz + ESP-NN 기준 **20~40ms 목표** (반드시 실측) |
| 루프 주기 | 8 Hz (125ms) → 추론 여유 3배 |

CenterNet 형태를 쓰는 이유: **바운딩 박스가 필요 없고 중심 좌표만 필요**하기 때문. 앵커·NMS 후처리가 사실상 불필요해 MCU에서 후처리 비용이 거의 0이며, 다중 인원도 히트맵 로컬 맥시마로 자연스럽게 나온다.

### 3.4 데이터 수집 — 레이더로 열화상을 자동 라벨링

TinyML 프로젝트의 최대 병목은 라벨링이다. 이 시스템은 **레이더가 라벨러 역할**을 하므로 수작업이 거의 없다:

```
1. 노드를 수집 모드로 부팅 (tools/capture_dataset.py)
2. 사람이 방을 자유롭게 이동 (레이더가 잘 잡히는 조건)
3. 레이더 (x, y) → 카메라 투영 → 열화상 픽셀 (u, v) 자동 라벨 생성
4. 프레임 + 라벨을 .npz로 저장
5. 정지 구간·특수 케이스(이불 덮고 눕기, 반려동물, 햇빛)만 수동 보정
```

**필수 수집 시나리오** (각 15~30분, 총 3~5시간 권장):

- 거리: 1m / 2m / 3m / 5m / 7m
- 자세: 서기 / 앉기 / 눕기 / 등돌리기
- 인원: 0명(네거티브 다수) / 1명 / 2명 / 3명
- 실내온도: 22℃ / 26℃ / 30℃ (에어컨 켠 상태·끈 상태 모두)
- 방해요소: TV 켬, 노트북, 전기포트, 햇빛 드는 오후, 반려동물, 선풍기, 커튼
- **네거티브가 전체의 40% 이상**이어야 오검출(FP)이 잡힌다

### 3.5 증강 (데이터 부족 대응)

```python
- 좌우 반전 (라벨 u도 반전)          # 가장 효과 큼
- 랜덤 시프트 ±2px, 회전 ±5°
- 글로벌 오프셋 ±3℃, 게인 ×0.9~1.1   # 실내 온도 변동 모사
- 가우시안 노이즈 σ=0.1K              # MLX90640 NETD
- 랜덤 데드픽셀 0~3개
- 합성 믹스: 사람 없는 배경 프레임 + 다른 프레임의 사람 패치 (max 합성)
```

마지막 "합성 믹스"가 특히 유효하다 — 배경 다양성 × 인물 다양성으로 데이터셋을 곱셈 확장한다.

### 3.6 손실 함수 / 학습

- heatmap: **focal loss** (CenterNet 변형), 타깃은 가우시안 σ=1.2 셀
- offset / logdepth: 양성 셀에서만 L1
- Adam, lr 1e-3 → cosine decay, 200 epoch, batch 64
- 조기 종료 기준: 검증 **중심 각도 오차 MAE**

### 3.7 양자화 및 배포

```
Keras → TFLiteConverter (full int8, representative_dataset 300프레임)
      → model.tflite (~30KB)
      → xxd -i → model_person.h
      → esp-tflite-micro (ESP-NN 활성) 로 추론
```

라이브러리 선택 주의:
- Arduino 공식 `Arduino_TensorFlowLite`는 **유지보수 중단** 상태 → 사용 금지
- 권장 ①: Espressif **`esp-tflite-micro`** (ESP32-S3 ESP-NN int8 가속 포함)
- 권장 ②: **Edge Impulse** 프로젝트에서 Arduino 라이브러리로 export (가장 빠른 프로토타이핑 경로, 내부적으로 동일 커널 사용)
- 대안: `Chirale_TensorFlowLite` (커뮤니티 유지보수 포크)

### 3.8 두 번째 모델 — 쾌적도 MLP (`AI가 알아서`의 실체)

사람을 "따라가는 것"만으로는 부족하다. 얼마나 세게, 몇 도로 틀지를 스스로 정해야 한다.

```
입력 6차원:
  [ 실내온도, 습도, 인물 표면온도(열화상 패치 평균), 거리 z,
    최근 5분 온도 변화율, 재실 지속시간 ]
        ↓  MLP 6→16→16→3  (약 400 params, <1KB)
출력:  P(덥다) / P(적정) / P(춥다)
        ↓
  덥다 → 설정온도 -1℃, 풍량↑, 직접 조준(Follow)
  적정 → 유지, 간접풍(Avoid)로 전환
  춥다 → 설정온도 +1℃, 풍량↓, 사람 회피 조준
```

**인물 표면온도**는 열화상만이 줄 수 있는 신호다. 같은 실내 26℃라도 방금 들어온 사람(피부 34℃)과 30분 앉아있던 사람(피부 32℃)의 필요 냉방량이 다르다.

**온디바이스 개인화**: 사용자가 리모컨으로 "더 시원하게/따뜻하게"를 누르면 그 시점의 입력 벡터가 라벨과 함께 NVS에 쌓이고, MLP **마지막 레이어만 SGD 1스텝** 업데이트한다(수십 µs). 클라우드 재학습 없이, 인터넷 없이 사용자에게 적응한다.

## 4. 추론 → 조준 파이프라인

### 4.1 히트맵 디코딩 → 각도

```
peak (cu, cv) = argmax(heatmap),  score = heatmap[cu,cv]
u = (cu + offset_x + 0.5) * 32/8     # 원본 해상도 좌표
v = (cv + offset_y + 0.5) * 24/6

az = (u/31 - 0.5) * HFOV_DEG        # 방위각 (+오른쪽)
el = -(v/23 - 0.5) * VFOV_DEG       # 고도각 (+위)
```

### 4.2 레이더 융합 (연관 + 선택)

```
레이더 타깃 목록 {(xr, yr, speed)} 중, 방위각이 az에 가장 가까운 것을 선택
  |az_radar - az| < ASSOC_GATE_DEG(=8°) 이면 연관 성립
    → r = sqrt(xr² + yr²)                (레이더 레인지 사용, 정확)
  연관 실패 (정지 인물 등)
    → r = exp(logdepth_head)             (CNN 추정 폴백)

3D 좌표:
  d = normalize([tan(az), tan(el), 1])
  P = r · d  +  SENSOR_OFFSET            → 대시보드 x, y, z (cm)
```

### 4.3 칼만 필터 (등속도 모델)

상태 `[x, vx, y, vy, z, vz]`, 6×6. 목적:

- 열화상 노이즈로 인한 좌표 지터 제거 → **서보 헌팅 방지** (기어 수명·소음에 직결)
- 사람이 가구에 잠시 가려져도(occlusion) 예측으로 추적 유지
- 미검출 2초 경과 시 `mode = "대기"`로 전이, 서보는 마지막 각도 홀드

측정 노이즈 R은 스코어에 반비례하도록 스케일링 — 확신 낮은 검출은 자동으로 덜 반영된다.

### 4.4 조준 기구학 + 냉기 강하 보정

```
yaw_geo   = atan2(Px, Pz)
pitch_geo = atan2(Py - VENT_Y, sqrt(Px² + Pz²))

# 냉기 제트는 밀도가 커서 낙하한다 → 먼 거리일수록 위로 조준
pitch_cmd = pitch_geo + K_DROP_DEG_PER_M * (Pz / 100)
```

`K_DROP`은 실측 캘리브레이션: 1m/2m/3m/4m 지점에 온도계를 두고 pitch를 스윕하며 최저 온도가 나오는 각도를 기록 → 선형 회귀. 초기값 약 **1.5°/m**에서 출발.

### 4.5 서보 구동 정책 (내구성 설계)

| 정책 | 값 | 이유 |
|---|---|---|
| 슬루 제한 | 3°/loop @8Hz = 24°/s | 급격한 기동 방지, 소음 저감 |
| 데드밴드 | 2° | 미세 진동 억제 |
| 드웰 타임 | 목표 변경 후 1.5초 유지 | 다중 인원 간 왕복 방지 |
| 정착 후 detach | 500ms 정지 시 PWM 해제 | 서보 지터·소음·전류 제거 |
| 각도 리밋 | yaw ±60°, pitch -20°~+30° | 기구 간섭 보호 |

### 4.6 다중 인원 정책 (`mode` 필드에 반영)

| mode | 동작 |
|---|---|
| `자동 추적` | 1명 → 직접 조준 |
| `평균 조준` | 2~3명 → 히트맵 상위 N개 가중 평균 위치 |
| `교대 조준` | 2~3명 → 20초씩 번갈아 조준 (스윕) |
| `간접풍` | 쾌적도 MLP가 "적정/춥다" → 사람 기준 yaw ±25° 회피 |
| `대기` | 2초 이상 미검출 |
| `절전` | 5분 이상 무인 → 추론 0.5Hz, IR로 에어컨 OFF |

## 5. "멀리서도 작동"의 3계층 설계

### 5.1 감지 거리

| 계층 | 방식 | 커버리지 |
|---|---|---|
| L1 | MLX90640(55°×35°) 단독 | 약 5~7m, 좁은 화각 |
| L2 | MLX90640(110°×75°, BAB) + LD2450 융합 | 약 6~8m, 넓은 화각 |
| L3 | **멀티노드 ESP-NOW 메시** | 노드 N개를 코너에 배치, 각자 로컬 추론 후 좌표만(12바이트) 브로드캐스트 → 마스터가 좌표계 변환 후 통합. 거실+주방 등 넓은 공간 |
| L4(옵션) | UWB DW3000 태그 | 사용자가 태그/스마트폰 소지 시 30m급, cm 정밀도. 열화상 사각지대 폴백 |

L3가 핵심이다. 센서 하나의 물리적 한계를 늘리려 애쓰는 것보다, **저가 노드를 분산하고 추론 결과만 합치는 것**이 TinyML의 본래 강점(각 노드가 독립적으로 판단)에 부합한다. 전송량이 프레임이 아니라 좌표라서 대역폭도 무시할 수준이다.

### 5.2 제어 거리 (인터넷 없이)

| 링크 | 실내 도달 | 용도 |
|---|---|---|
| **ESP-NOW** | 벽 관통 20~30m, 개활 100m+ | 전용 리모컨(ESP32+OLED+버튼). **라우터·인터넷 완전 불필요**, 페어링은 MAC 등록만 |
| **BLE** | 10~30m | 스마트폰 앱/웹블루투스 |
| **LoRa SX1262 (920MHz, 국내 ISM)** | 건물 전체~수백m | 사무실·상가 다중 실 원격 |
| **IR** | 5~8m 직선 | 기존 에어컨 리모컨 호환 폴백 |
| 로컬 WiFi AP | 반경 15~20m | 노드 자체가 AP → 브라우저 대시보드 (§6.3) |

즉 "멀리서도 작동"이 **인터넷 유무와 완전히 무관**하다.

## 6. 오프라인 우선 소프트웨어 구조

### 6.1 절대 규칙

```cpp
// 금지 — 기존 firmware/smart_air_guider/smart_air_guider.ino:81
while (WiFi.status() != WL_CONNECTED) { delay(300); }   // 제어 루프 정지

// 채택 — 상태 머신 + 논블로킹 재시도
loop() {
  runControlCycle();     // ① 항상 8Hz로 실행. 네트워크 코드 없음
  serviceNetwork();      // ② 남는 시간에 best-effort. 실패해도 즉시 리턴
}
```

**제어 루프는 네트워크 함수를 단 한 줄도 호출하지 않는다.** 이게 요구사항 "인터넷이 안 되는 상황에서도"의 구현 그 자체다.

### 6.2 링버퍼 + 백필

```
LittleFS 순환 로그 (레코드 32B × 4096 = 128KB, 약 2.2시간 @2s)
  오프라인 → 계속 append (오버플로 시 가장 오래된 것부터 덮어씀)
  온라인 복구 → 100건씩 배치 POST /sensor/bulk, ACK 받은 만큼 헤드 전진
```

### 6.3 오프라인에서도 기존 대시보드 그대로 쓰기

노드가 **동일 스키마의 `GET /sensor`를 로컬에서 직접 서빙**한다 (CORS 허용 + mDNS `smartair.local`).

- 공유기는 있고 인터넷만 끊긴 경우 → STA 모드, `http://smartair.local/sensor`
- 공유기조차 없는 경우 → SoftAP `SmartAirGuider` 발행, `http://192.168.4.1/sensor`

프론트엔드는 fetch URL만 폴백 순서로 바꾸면 코드 변경이 사실상 끝이다:

```js
const ENDPOINTS = [
  "http://smartair.local/sensor",                  // ① 로컬 (인터넷 불필요)
  "http://192.168.4.1/sensor",                     // ② 노드 SoftAP 직결
  "https://smart-air-guider.onrender.com/sensor",  // ③ 클라우드
];
```

### 6.4 성능 저하 사다리 (Graceful Degradation)

| 레벨 | 조건 | 동작 | `mode` |
|---|---|---|---|
| L0 | 정상 | 열화상 CNN + 레이더 융합 | `자동 추적` |
| L1 | 레이더 통신 두절 | 열화상 단독 + CNN 깊이 추정 | `자동 추적(열화상)` |
| L2 | I2C 열화상 실패 | 레이더 단독 추적 | `자동 추적(레이더)` |
| L3 | 둘 다 실패 | PIR 트리거 + 기본 스윙 | `기본 스윙` |
| L4 | 서보 이상 | 중립 복귀 후 정지, IR로 본체 스윙 위임 | `수동` |

네트워크 두절은 **이 표에 등장하지 않는다** — 성능 저하 요인이 아니기 때문이다.

### 6.5 워치독

Task WDT 8초. 추론 태스크는 Core 1, 네트워크 태스크는 Core 0에 핀 고정 → WiFi 스택 지연이 추론 지터에 영향을 주지 않게 분리.

## 9. 예산 (대략, 국내 소매 기준)

| 품목 | 개략가 |
|---|---|
| ESP32-S3 개발보드 | 1.5~2.5만 |
| MLX90640 모듈 | 6~9만 (설계 핵심 비용) |
| HLK-LD2450 | 1.5~2.5만 |
| 서보 2 + 브래킷/3D 프린트 | 2~3만 |
| DHT22/SHT31, PZEM-004T, IR, 5V3A 전원 | 3~4만 |
| **1노드 합계** | **약 15~22만** |
| ESP-NOW 리모컨(옵션) | 2~3만 |

MLX90640이 비용의 절반이다. 예산 제약이 크면 **AMG8833(8×8, 2~3만)**로 시작 가능 — 입력을 8×8×2로 줄이면 모델이 1/4로 작아지고 파이프라인은 동일하다. 다만 각도 분해능이 7.5°/픽셀이라 조준 정밀도가 떨어지므로, offset 헤드의 서브픽셀 보정 의존도가 커진다.

## 11. 이 설계가 요구사항을 만족하는 근거 요약

1. **사람 인식** — 열화상 CNN이 형상·시간 패턴을 학습해 사람과 열원/반려동물을 구분. PIR 임계값 방식으로는 불가능한 판별.
2. **추종** — 히트맵 서브픽셀 → 각도 → 칼만 → 슬루 제한 서보. 좌표가 이산 3존이 아니라 연속값.
3. **원거리** — 감지는 열화상+레이더 융합 및 ESP-NOW 멀티노드 확장, 제어는 ESP-NOW/LoRa/BLE. 모두 인터넷 비의존.
4. **오프라인 AI** — 추론·융합·제어·쾌적도 판단·개인화 학습이 전부 MCU 내부. 네트워크는 관측/백필 전용이며 제어 루프에서 호출되지 않는다. 링버퍼 + 로컬 HTTP 서버로 대시보드 UX까지 오프라인 유지.
